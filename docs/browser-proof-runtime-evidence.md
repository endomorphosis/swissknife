# Browser theorem and WASM ZKP runtime evidence

SWR-139 requires an actual Playwright browser execution, not a happy-dom or
Node-only assertion. The machine-readable execution contract is
[`browser-proof-runtime-evidence.json`](./browser-proof-runtime-evidence.json).
The recorded runtime command passed all 81 assertions: 27 each in Chromium,
Firefox, and WebKit. It records the observed outcome, but does not invent a
timestamp, proof byte string, or performance value that was not preserved by
the runner.

## Required execution

Run the dedicated suite, which runs the same source-level assertions in
Chromium, Firefox, and WebKit:

```bash
npm run test:browser-proof-runtime
```

The suite is configured in
`build-tools/configs/vitest.browser-proof-runtime.config.ts`; its browser
environment is Playwright. Its result is valid only when every required engine
passes. Per-run reports, if retained, belong in
`test-results/browser-proof-runtime/` and must retain their command, engine,
timestamp, and raw test status.

The release validation gates remain:

```bash
npm run typecheck:browser
npm run test:browser-compat
npm run audit:bundle-host-leakage
```

## What executes in each browser

The theorem default is `typescript-truth-table`. It generates a complete,
digest-bound truth-table artifact for `((p && (p -> q)) -> q)` and verification
recomputes the rows and digest; it does not trust a proof-shaped response. A
refuted formula, altered row/digest/formula, malformed request/envelope, and
unavailable backend selections are all asserted as negative outcomes.

The ZKP default is `browser-schnorr-wasm`, a browser-native Schnorr
Fiat-Shamir backend. It instantiates the committed `schnorr-field.wasm.b64`
helper, generates a seeded proof for the fixed audited-policy public input, and
verifies that generated artifact through a fresh backend. The fixture is fixed
to seed `139`, statement `O(log_access)`, and public input
`{"policy":"audit","subject":"browser-proof-runtime"}`
so the proof bytes and public inputs can be compared across invocations without
manufacturing an expected proof.

The suite also rejects tampered statement/response fields, malformed ZKP input
and envelopes, fabricated success envelopes, and simulated proof identifiers.
For theorem workers it records typed crash, timeout, deserialization, and
caller-side-verification failures. In particular, a worker posting
`{ kind: "proved" }` is not evidence until the caller independently verifies
its artifact.

## Backend-selection boundary

Browser defaults never select a Python runner, native host binding, simulated
prover, mock-success backend, or fabricated proof result. The theorem preflight
returns `BROWSER_PROVER_BACKEND_UNAVAILABLE` for unsupported identifiers. The
ZKP policy rejects simulated and other non-production identifiers before proof
generation. `wasm-prover-browser-purity.test.ts` and the bundle-host-leakage
audit provide the static and bundle-level complement to the per-engine runtime
checks.

The complete fixture definitions, expected artifact fields, selection records,
and negative receipt codes are in the JSON contract. This separation is
intentional: the contract is reviewable in source control, while a pass result
must be generated by the browser test runner.
