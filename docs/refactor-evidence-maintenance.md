# Refactor Evidence Maintenance

This runbook keeps the SwissKnife refactor plan, service boundary contract,
task board, validation commands, and release evidence synchronized after each
milestone.

## Sources Of Truth

| Artifact | Role | Updated by |
| --- | --- | --- |
| `implementation_plan/docs/38-swissknife-repository-refactoring-plan-2026-07-08.todo.md` | Refactor objective, phase summary, task board status, milestone validation commands, and acceptance notes. | Humans or agents completing backlog work. |
| `src/module-ownership.json` | Machine-readable source module ownership, runtime classification, public entrypoints, and allowed/forbidden import rules. | Boundary/refactor changes. |
| `src/services/MODULE_BOUNDARIES.md` | Human-readable service boundary contract for `src/services` and owned service submodules. | Service ownership or runtime-boundary changes. |
| `docs/source-module-boundaries.md` | Human-readable repository-wide source module contract. | Top-level module ownership changes. |
| `docs/release-browser-gates.md` | Release gate inventory and evidence freshness policy. | Release gate command or evidence group changes. |

Generated evidence should be regenerated by its command, not hand-edited.
Manual recertification with `npm run evidence:freshness:update` is only for
recovery after the evidence content has been reviewed.

## Milestone Checklist

After each SWR milestone:

1. Update the task board entry with the actual status, outputs, validation
   command, and concise evidence/acceptance note.
2. Update `src/module-ownership.json` when files move, public entrypoints
   change, or import/runtime rules change.
3. Update `src/services/MODULE_BOUNDARIES.md` for service ownership or
   browser/host service-boundary changes.
4. Update `docs/source-module-boundaries.md` for top-level module changes.
5. Run the milestone validation command and regenerate any evidence it owns.
6. Link the evidence artifact from the plan or acceptance note when the task
   depends on a generated report.
7. If release gates changed, update `docs/release-browser-gates.md` and run
   `npm run release:gate` when practical.

## Current Refactor Gate Snapshot

The documentation gate for SWR-010 is:

```sh
test -f implementation_plan/docs/38-swissknife-repository-refactoring-plan-2026-07-08.todo.md && cd swissknife && npm run services:audit
```

`services:audit` is intentionally the minimum synchronization check because it
refreshes the service/source boundary audit payload and the module-boundary
freshness receipt. Broader release readiness is covered by `npm run
release:gate`, which also checks typecheck, fast tests, browser compatibility,
web bundle policy, evidence freshness, and MCP/glasses evidence.
